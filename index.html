01Toy ECC Encryption (secp256k1 with Restricted Key Space)

This educational implementation uses the actual secp256k1 curve equation and generator. For experimentation, the private scalar is restricted to 1 ≤ d ≤ 2ᵇ. Encryption uses an EC-ElGamal-style ephemeral point and derives a demonstration keystream from the shared point using SHA-256. This is not production-grade ECIES: it has no authenticated encryption, and the intentionally small private-key space makes it insecure.

System ready. Generate a key pair to compute Q = d·G on secp256k1.
Algorithm: Key generation: Q = dG. Encryption: choose fresh k, compute C₁ = kG and S = kQ, derive a keystream from S.x, then C₂ = M XOR keystream. Decryption: compute S = dC₁ and XOR C₂ with the same derived keystream. Because dC₁ = d(kG) = k(dG) = kQ, both parties derive the same shared point.

02The Classical Caesar Cipher

Caesar is a symmetric monoalphabetic substitution over ℤ₂₆. For letters A–Z, encryption is Eₖ(m) = (m + k) mod 26 and decryption is Dₖ(c) = (c − k) mod 26. Spaces and punctuation are preserved.

03Architectural and Statistical Comparison

The schemes differ in key management, transformations, and the assumptions under which an attacker can recover the plaintext.

DimensionToy ECCCaesar cipher
Paradigm Public-key construction: public Q and private scalar d, combined with a symmetric keystream demonstration. Symmetric substitution; sender and receiver share shift k.
Mathematics Point arithmetic on secp256k1: y² = x³ + 7 (mod p). Modular addition/subtraction in ℤ₂₆.
Key space in this lab 2ᵇ candidate private scalars, where b is adjustable from 6 to 16. This restriction is deliberately insecure. 26 possible shifts, including the identity shift 0.
Encryption Random ephemeral k means the same plaintext can yield different ciphertexts. Deterministic: the same plaintext and shift yield the same ciphertext.
Statistical properties The SHA-256-derived demonstration keystream obscures direct letter-frequency patterns, but this toy construction is not a proof of secure encryption. Letter counts are preserved under relabeling; language redundancy makes statistical recovery possible.
Attack surface Bounded discrete-log search can recover d because the candidate range is tiny. Try all 26 shifts or rank candidates using language statistics.

04Statistical Cryptanalysis of Caesar

The chi-square method tests all 26 shifts. For each candidate decryption, it compares observed letter counts Oᵢ with expected English frequencies Eᵢ and selects the lowest score: χ² = Σ (Oᵢ − Eᵢ)² / Eᵢ. It is a heuristic: short texts or unusual language can produce the wrong key.

05Attacking the Bounded ECC Private Key

This attack does not analyze letter frequencies. It tests candidate scalars against the public key Q = dG. Since the key is restricted to a small interval, exhaustive search and Baby-Step Giant-Step (BSGS) can recover it. The implementation uses real secp256k1 point arithmetic.

Generate an ECC key pair in Section 1 first, then run an attack.
Why this does not scale to correctly configured ECC: for a roughly 256-bit group, generic classical discrete-log attacks require on the order of 2¹²⁸ group operations with square-root algorithms. That is not practically feasible with current classical resources. This demonstration is intentionally weakened by its tiny bounded key space.

06Security Discussion and Limitations

Restricted key space

  • A small interval allows direct enumeration of every candidate d.
  • Recovering d undermines the public-key confidentiality associated with that key pair.
  • BSGS reduces the search time to about O(√N) group operations at the cost of O(√N) memory.

Toy construction limitations

  • The SHA-256 keystream derivation is illustrative, not a standardized KDF/ECIES protocol.
  • The ciphertext has no authentication tag; bit flips may alter decrypted plaintext undetected.
  • Never reuse ephemeral k in real systems. Reuse can reveal relationships between plaintexts when the same keystream is used.
  • Real deployments require vetted cryptographic libraries, point validation, a KDF, and authenticated encryption.

Caesar limitations

  • Only 26 shifts exist, so exhaustive search is trivial.
  • Unigram frequency analysis works better with longer ordinary-language texts.
  • Bigram and dictionary heuristics depend on the language and quality of their model; short or atypical texts may defeat them.

This page is an educational laboratory, not a secure encryption tool. Do not use this implementation to protect real messages or data.
